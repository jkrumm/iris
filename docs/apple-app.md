# iPhone app reference

Composition, thread view, reply artifacts on screen, the artifact island, take UI, live preview, kinds and modes, spacing, strings and UI-test detail. Rules to follow: `apple/AGENTS.md` and `apple/Packages/IrisUI/AGENTS.md`. Design: TDD §4.

- **App composition:** `-IrisFakeCapture` (every UI test, `make run-sim`) runs the fake API, silent media and fake capture (the real outbox on fake audio; `-IrisFakeOffline` fails the first create of each kind); without it the app is
  production: server URL + device token from Settings → Connection (token in the Keychain, URL in `UserDefaults`), one `ReconfigurableAPIClient`
  shared by every model. Nothing saved: the app opens on Settings and loads nothing. Memo audio and speech are downloaded with the bearer header by
  `MediaDownloader.shared` (one `URLSession`, single-flight per URL, `evict(memoID:)` when History deletes or hides a memo (the cache check runs on the same actor as eviction, and a launch sweep removes cached files untouched for 14 days): it returns at once, scans off the main actor and cancels that memo's downloads still on the wire, so none lands afterwards) and played from the file (no `AVURLAssetHTTPHeaderFieldsKey`, TDD §4 "Authenticated media"). `ReplyImageStore` loads at most three files at once. `MemoPlayer` follows a periodic time
  observer; call `teardown()` when the screen goes away. The unsigned simulator build (`CODE_SIGNING_ALLOWED=NO`) has no Keychain (`-34018`): the
  Keychain round-trip unit test cancels there and is device-verified only. `StatsModel`/`SettingsModel`/`HistoryModel` `load()` drop a stale answer (generation guard). Settings' server row is `ConnectionStatusLine(connection:link:)`: the health probe from when Settings appeared plus `HistoryModel.link` (`ServerLink`: what the event stream and list loads last saw), so a dropped network or Tailscale, or a gateway 502/503/504 without a contract body (a proxy in front of a server that is not answering), reads "Unreachable" with "Server not reachable — is Tailscale on?" and a 401 "Token rejected" instead of a stale "Connected". When the two disagree the newer observation wins (`SettingsModel.probedAt` vs `HistoryModel.linkObservedAt`).

- **Thread view** (`ThreadView` / `ThreadModel`, TDD §4 "Thread view"): the History row of every Hermes memo pushes it (`Memo.isConversation` in IrisCore, one rule with the Mac's chat layout; transcribe-mode and deleted memos keep `MemoDetailView`), anchored at that memo (`ThreadModel(memo:)`, the anchor's own turns until `GET /v1/threads/:id` answers). The bottom is `ThreadReplyBar` over IrisCore's `ReplyBarModel`: an inline field (sent through `ComposerModel` and the outbox; held on the device while the first memo is before `act`, which has no thread yet) and hold-to-talk / locked recording (needs a thread id). Details are one sheet (`MemoDetailsSheet`: kind chip and meta line, players, then IrisUI's `MemoDetailsContent`: step waterfall with Retry, cost, copy rows, "Hermes used", ids; open by default, the Details line folds it; the Mac's popover draws the same view) from the toolbar's info button (`thread.details`; `memo.details.open` on `MemoDetailView`, which no longer carries an inline section). In a conversation the sheet opens on the newest memo and steps to earlier ones (`memo.details.previous` / `.next`, "Answer 2 of 3" as subtitle; `ThreadModel.memos`); a bubble's context menu (`ConversationTurnList(onDetails:)`) opens it on that bubble's memo. A failed turn has Retry under it (`onRetry` → `ThreadModel.retry`, `thread.turn.retry`), a failed transcript memo keeps its retry bar, so a failure never needs the sheet. The turns come from IrisCore's `ConversationTimeline`, map to IrisUI's `ConversationTurn` and render through `ConversationTurnList` (`Style.phone` / `.mac`, the Mac's `MacConversationView` too), derived from
  `GET /v1/threads/:id` (user, assistant, pending with step dashes, failed) and reloads on the memos' History revisions. Replies render through `IrisUI`'s `MessageContentView`: `MessageBlock.split`
  cuts markdown into Textual text, a table (a grid that scrolls sideways when too wide, columns aligned by the delimiter row) and Mermaid fences numbered like the server's `ReplyBlock.index`; `MessageContentView(markdown:isStreaming:)` takes a growing reply (80 ms / newline buffer, chunked live tail, stabilized half-written markup; math by `MathSpans`; TDD §4 "Prose renderer"); diagrams are the PNG of the current appearance
  through `ReplyImageStore` and the authenticated `MemoMediaSource.asset`. Textual is pinned `exact: 0.5.0` in `IrisUI` only. Voice replies go through the `VoiceReplyCapture` port (`OutboxVoiceReplyCapture`: the real
  capture session and outbox, on fake audio under `-IrisFakeCapture`). The fake sample data holds a chat thread with every block type (`SampleData.chatThreadID`) and a Hermes thread with a turn in flight.
  `ThreadReplyBar` is one row of icons (keyboard, hold to talk, locked recording = tap to start, send or cross to end; both voice takes use the same `beginVoice`/`endVoice`). Code is highlighted with the JetBrains
  Light/Dark colors of `IrisUI/Theme/CodeColors.swift` (hand-written, not generated: basalt-ui has no syntax tokens; table in TDD §4 "Reply layout and code themes"); Textual tokenizes after the first frame, so snapshots show no token colors.

- **Reply artifacts on screen** (Issue 728, TDD §4 "Artifacts in the conversation", `IrisUI/Components/Artifact`): `MessageBlock.split` yields `.artifact(kind, index:, source:)` per `iris-show` / `iris-doc` fence (numbered per kind like the server's `ReplyArtifact.index`); `MessageContentView(artifacts:)` takes the memo's `replyArtifacts` as `ArtifactAsset`s keyed by (kind, index). A show spec is an inline island, a document a titled card; both open `ArtifactViewer` (full screen on iOS, a window on the Mac via `\.openArtifact`) with Share and Copy. Files come through `ArtifactStore` (`\.artifactStore`, the `ReplyAssetLoader` port = `MediaDownloader` with the bearer header; the WebView loads nothing), at most three islands are live per conversation (`ArtifactIslandBudget`, `\.artifactIslandBudget`; the rest are snapshots), a failed or refused artifact is its fence as code with a retry, an HTML document is its own CSP-locked inline page (no script, no network), never the bundled renderer. IrisCore's `ShowSpec` is the Swift side of `artifacts.show-spec`.

- **Artifact island** (`IrisUI/Components/Artifact`): `ArtifactWebView(entry:payload:)` is one sandboxed SwiftUI `WebView`/`WebPage` per artifact (`.bundled(file)` from `Resources/Artifact`, or `.html(string)` with no scripts) that sizes itself (`ArtifactIsland.height`), takes its colors from the Theme (`ArtifactTheme`: `--iris-*` CSS variables, light/dark) and loads offline. Content comes only from the custom scheme `iris-artifact://` (`ArtifactSchemeHandler`: `app/<flat file>` bundled, `doc/page` inline) under a CSP (bundled: own-scheme script/style, `connect-src` none; inline: styles, no script); `ArtifactNavigationPolicy` lets http(s)/mailto/tel links leave through `openURL` and cancels every other navigation. The bridge is the message handler `iris` in the isolated content world `iris-bridge` (theme variables, ResizeObserver height, `ready`); the page receives data through `window.iris.render(payload)`. Debug screens: `-IrisArtifactSpike` (+ `-IrisArtifactIslands <n>`) on iOS, `-IrisMacSnapshot` adds `artifact-island*.png` and `artifact-memory.txt`; `-IrisArtifactSample cards|viewer` (`Iris/ArtifactSample.swift`, DEBUG) shows the sample artifact reply (chart, table and document card over the fake media source) or the viewer on the sample document, and `-IrisMacSnapshot` adds `artifact-cards`, `artifact-cards-dark`, `artifact-viewer`, `artifact-viewer-dark`; `make proof-apple` collects all (iOS: `artifact-{light,dark,cards-light,cards-dark,viewer-light,viewer-dark}.png`). The sample thread `SampleData.artifactThreadID` (oldest, so History lists it last) carries the three artifacts; its asset ids serve the spec JSON / markdown through `FakeMediaSource`. On the Mac a card's Open is the `artifact` window (`WindowGroup(for: ArtifactViewerRequest.self)`, `MacWindowID.artifact`); iOS leaves `\.openArtifact` nil, so the card presents the full-screen viewer.

- **Optional summarize, money, offline History** (Wave 16 I2, TDD §4): a `notified` memo with `summary == null` reads as done; History and the detail header show the transcript clipped to 60 characters, and the waterfall shows its failed `summarize` as failed-but-optional (`StepWaterfallRow.optionalNote`) with [Retry from Summarize]. Money is `StepText.dollars` (locale, no fixed `$`; two decimals from a cent, four below so a real cost never reads `$0.00`, `<$0.0001` under a hundredth of a cent, zero `$0`). The detail's waterfall is collapsed to its Details line (steps and ids; `MemoDetailModel.isWaterfallExpanded`, a failed memo opens it) with contiguous bars (`WaterfallBuilder`); transcript and reply copy as plain text (`MemoDetailModel.copy`, `PlainMarkdown`); the take's meter is `InputLevel` (dB scale, −50…−10 dBFS). History without a saved connection shows a connect prompt that opens Settings. History's hidden set (discarded takes whose server `DELETE` is pending) is persisted (`HiddenMemoStore`) and cleared by `CreatedMemoLog.settle`. The fake API answers a typed memo (`FakePipelineUploader.create`). Every UI test class derives from `IrisUITestCase` (starts the app through `start(_:)`, ends it at teardown, tolerates a stalled terminate).

- **Take UI** (Wave 15 I4, TDD §4 Screens): one `TakeController` (start with its Live Activity, stop, cancel, pause, mic switch; the intents and the screens share it) under a `TakeModel` that follows `CaptureSession.updates()`. A running take is the full `TakeScreen` (a cover, opened on start), or the compact `TakeBanner` once minimized:
  every screen pins it under its navigation bar with `.takeBanner()` (a banner over the whole `TabView` would cover the bar's buttons). The record control is the tab bar's bottom accessory (`RecordRow`: three visible buttons, no hidden gesture: a large primary Hermes capsule (`record.start`, the default, `sparkles` because the SF Symbols have no robot glyph), and Transcribe (`record.transcribe`) and Text (`record.text`, the one entry to the composer) as the same capsule height in a tinted secondary fill, icon-only when the bar is minimized); `isEnabled:` hides it during a take on iOS 26.1+, disabled on 26.0);
  memo detail and thread hide the tab bar, which does not hide the accessory (Apple DTS, iOS 26.1), so their bottom bars (`DetailActionBar`, `ThreadReplyBar`) register through `.hidesRecordAccessory()` (`RecordAccessoryPresence`, counted, injected by `RootView`) and `isEnabled:` takes the control off while one is shown; on 26.0 it stays (the banner still shows). A thread's hold-to-talk (`TakeRequest.holdToTalk`) is not shown by the banner; a take that merely continues a thread is a normal take. The Live Activity views are IrisUI's (`LiveActivityPanel`, `Island*`, `ActivityStageDashes`; plain `ActivityPresentation` values, no IrisCore) and the widget maps `ContentState` onto them;
  Stop / mic swap / pause are `LiveActivityIntent`s (`StopMemoIntent`, `SwitchInputIntent`, `PauseMemoIntent`) that call the same `TakeController`. The step progress of a processing memo is the four stages record, upload, process, done from the phase alone (`ContentState` has no step field; per-step progress needs the server to push one). A new take's activity says "N earlier memos are still sending" in `headline` (client phases only).

- **Continued transcripts** (Issue 1770; server model: `docs/server-design.md` "Transcript threads"): a transcript is a first `transcribe` memo plus recordings that continue it, each its own memo with its own audio, steps, retry and delete. The detail has **Continue recording** (`detail.continue`, under Copy transcript; any part offers it, to the first part's id): `TakeModel.start(mode: .transcribe, threadID:)` binds a Transcribe take to the transcript, and `threadId` rides the outbox item like a Hermes reply's, so a continuation recorded offline queues like any take. `Memo.isTranscriptPart` (IrisCore: `transcribe` and a `threadId` that is not its own id) marks a part: `HistoryModel` leaves it out of `sections` / `memoIDs` (the list keeps it in `memos`; the open transcript reads its revision through `transcriptRevision(of:)`), so History shows the transcript once, as its first part's row. `MemoDetailModel` loads `GET /v1/threads/:id` for a memo with a thread and draws one bubble per part oldest first (a part still transcribing is a pending bubble); **Copy transcript** and the row's swipe Copy put `TranscriptText.whole(of:)` (the parts' texts, a blank line between) on the pasteboard, a bubble's own copy only that part. Only the opened recording has a player bar, and the Details sheet stays on the opened memo (a later part's own player and steps are not reachable yet). A deleted first part orphans the later ones: they have no row and open only from a notification. The Mac pane reads the same thread and shows one Transcript section per part; recording a continuation on the Mac waits for row mac-transcribe-and-filters' Transcribe action. The fake composition continues a transcribe memo like the server (`FakeAPIClient` promotes the first part; `FakePipeline` ends a transcribe memo at its text); `SampleData.transcriptThreadID` is the two-part sample, oldest in History.
- **Live preview** (Wave 19 R1, TDD §4 "Live preview"): the take screen shows the on-device transcript as it is spoken (`SpeechTranscriber`, iOS 26), display only: never uploaded, stored, logged or put into telemetry; the server transcript is the truth. `PreviewTap` (IrisCapture) is an additive, bounded, read-only stream of the samples the recorder accepts; `LivePreviewModel` (`TakeModel.preview`) consumes a `LivePreviewEngine` (production `SpeechAnalyzerPreviewEngine`, fake `FakeLivePreviewEngine`) handed to `TakeController` as a `LivePreviewSource` (`nil` = none). Absent language or model (checked at runtime: supported and in `installedLocales`), a failing analyzer, or no source: no preview, the take goes on; the app never starts a model download. The analyzer does not run in the Simulator, so only the fake is tested there; no `NSSpeechRecognitionUsageDescription` (that is `SFSpeechRecognizer`). Never log or store what it hears.

- **Two modes, the kind chip** (Wave 21 A1, TDD §4 "Two modes and the kind chip"; Iris stopped routing, Hermes decides): `MemoMode` is `hermes` (default) and `transcribe`; any other wire value reads as `hermes`. The composer (the record row's Text button, a thread reply, the History [+]) has two send targets, "Send to Hermes" and "Transcribe" (a reply bound to a thread offers Hermes only). A memo's chip is `kindLabel` (`MemoPresentation`): the memo's `kind` capitalised like the server's alert, else an old memo's route name, "Transcript" for mode `transcribe`, "Hermes" while nothing is known; `KindChip` is neutral, `KindPalette` colours the known kinds (a free-form kind is data: `Text(verbatim:)`). The detail shows `actions` as one quiet line under the reply ("Hermes used: capture, terminal"). History filters by kind from the kinds present in the loaded pages (`HistoryFilters`, `?kind=`) plus Favorites, Threads (`thread=true`) and Archived; stats series are per kind (top four by count, `Other`, `Transcript`). An old memo parked at `needs_route` reads "Not delivered" and offers no routing. `SpeechPlayer` is the one spoken-reply player (`Memo.isSpeakable`, notified + a reply + not deleted, is the one rule: the media sources, hence Play and `PlayReplyIntent`, and `SpokenReplies`): the detail's Play,
  `PlayReplyIntent` (an `AudioPlaybackIntent` in `Iris/Intents`, compiled into the widget; the done Live Activity has a Play button, compile-checked only) and spoken replies (Settings toggle, `SpokenReplies`: foreground only, memos this device created, once each; the take sample is taken when `memo.done` arrives, not after the task hop); it never interrupts: while a reply or the open detail's recording plays or any take is open (`TakeModel.isCapturing`) the memo is skipped for good, no queue (Wave 17 I3). The other direction (Wave 18 I1): `TakeController.captureActive` is one synchronous flag, set before a start awaits anything (a thread's hold-to-talk too, `OutboxVoiceReplyCapture.claim`) and cleared only after the session has ended; a start also pauses the reply, the open detail's recording and any speech still downloading (`SpeechPlayer.pauseForTake()`). Every playback start reads the flag at the moment it starts (`SpeechPlayer.captureActive`); nothing resumes by itself. Settings → Microphone edits the active route's mic rule (`MicRulesModel` over `RouteManager`;
  `RouteSnapshot.outputNames` is display only). The fake API's samples carry kinds and actions, one old memo with a route and no kind, and a transcript memo.

- **Spacing:** no spacing literals in views; `Theme.Spacing` (`IrisUI/Theme/Spacing.swift`) holds the steps (`hair` 2 … `xl` 24) and the roles (`screenMargin` 20, `sectionTop`/`sectionBottom`, `rowVertical`, `rowColumnGap`, `rowLineGap`, `chipGap`, `barInset`, `barGap`, `cardInset*`), taken from the mockups' CSS. A missing value is added there with its mockup source. Control sizes (button and dash dimensions) are not spacing. No screen draws a title block (History, Stats, Settings, Diagnostics: the tab bar says where you are, content starts under the status-bar scrim). History hides the navigation bar and has a bottom search + filter row (`HistorySearchBar`, two 44 pt targets), so everything sits on the 20 pt `screenMargin`. The memo detail (iOS and Mac pane) reads header (with a prominent Copy transcript button, `detail.copy`) → reply → transcript (clamped to 8 lines behind Show full message, or folded to the memo's `transcriptGist` when it has one; with the player) → the toolbar's Details sheet (steps, cost per step, attempts, ids, retry); per-screen deltas against the mockups: `docs/design/fidelity/`.

- **Strings:** English is the source, every user-facing string has a `de` entry (TDD §4 "Localization": forms, glossary, what is never localized). Catalogs per target: `Iris/Resources/` (+ `InfoPlist.xcstrings`), `IrisWidgets/Resources/`, `IrisMac/Resources/` (+ `InfoPlist.xcstrings`), `IrisUI/Resources/`. A SwiftUI literal is a `LocalizedStringKey`; a `String` is `String(localized:comment:)`; intents, widgets and controls take a `LocalizedStringResource` literal; in a package every one of them passes `bundle: #bundle`. `Text(verbatim:)` for data. A key's `%lld` / `%@` follows the interpolated type, a literal `%` is `%%`, a shared `Iris/*.swift` file needs its keys in each target's catalog that compiles it. `make check-strings` (in `check` and `check-apple`) fails on a missing or untranslated `de`, a `de` whose specifiers differ from the key's per argument index (every plural leaf too; German plurals need `one` and `other`, no empty branch, no index with two types), a positional key (`%1$lld`: the compiler extracts `%lld`), a stale key, a hard-coded literal, a `%lld` / `%@` mismatch it can see, a `Text(a ? "x" : "y")` or `Text("a" + "b")`, and in a package any literal that is not `Text(_, bundle: #bundle)` / `String(localized:, bundle: #bundle)` / `LocalizedStringResource(_, bundle: #bundle)` (only `#bundle` / `.module` count; modifiers like `.accessibilityLabel("x")` included); a step name shown to the user is `MemoStep.title`, never `rawValue`; `// l10n:ignore <why>` marks real data. Run the app in German with `-AppleLanguages "(de)" -AppleLocale de_DE`.

- **UI test waits:** a test never reads `exists`/`frame` of an element that may not be there in a loop; it uses `IrisUITestCase.waitForPresence` / `waitForAbsence` / `revealRow(containing:in:)`, which ask again when a query times out on a loaded runner (TDD §4 "UI tests on the hosted runner"). A test never races a wall-clock timer of the app: it holds the state (`-IrisUndoSeconds 600` for the undo toast, `-IrisCopiedSeconds 600` for the detail's "Copied"), waits on the element that shows a state (Settings' `settings.outbox.retry` only exists once the attempt failed), and drags slowly (`withVelocity: .slow`) until the outcome shows.

- **UI tests and the clock:** the fake sample memos are relative to a clock, and the UI tests pin it (`-IrisSampleNow <ISO-8601>`, `Tests/UITests/SampleClock.swift`: noon today),
  so History looks the same at 00:30 and at 14:00 (a memo from 90 minutes ago is on another day for the first hour and a half after midnight). The fake
  server's clock starts there and runs on, so a memo created in the app is newer than the samples. `HistoryDaySection.id` is (day, occurrence): two sections of one day must not share an id (SwiftUI dropped the rows).
