# Mac app reference

Capture, server binding, popover, windows, composer, notifications, telemetry and snapshots of `IrisMac`. Rules to follow: `apple/IrisMac/AGENTS.md`. Design: TDD §5.

- **Mac capture** (Wave 18 M2, TDD §5): the global key is `KeyboardShortcuts` 3.1.0 on Carbon (no permission prompt, no `CGEventTap`), default **Control-Option-M** (Control-Option-Space is the system's input-source switch; research: `docs/research/2026-10-31-mac-hotkey.md`), recorded in Mac Settings. A press toggles a take through `RecordingPanelModel` → the `TakeEngine` port (`CaptureTakeEngine` over the iPhone's `CaptureStack`, `APIOutboxUploader` and the persistent outbox in the app container; `MacCaptureStack`) → the floating `NonActivatingPanel`. macOS has no `AVAudioSession`: `MacAudioSessionController` is a no-op and `DirectoryRouteManager` over Core Audio (`CoreAudioDeviceDirectory`) is the route manager; picking a microphone sets the system default input and the take's end puts the old one back. The original is persisted first (`RecoveringRouteManager`, `InputRecovery` in `UserDefaults`) and a kill mid-take is undone at the next launch (`RecoveringRouteManager.recover`). `-IrisFakeData` runs `FakeTakeEngine`, `FakeMicrophonePermission` and `FakeTakeHotkey` (no microphone, no prompt, no registration); the panel's microphone chip names the device in use (cut in the middle past `Theme.Spacing.panelMicNameMax`; the panel is 380 pt wide for it) and its menu checks the current one; the snapshot run adds `recording.png` (the real panel) and `recording-refused.png`. An unsigned build (CI, `check-apple`) never records; the stable-signing recipe and the hands-on rows (microphone prompt, real hotkey, a real take) are in `docs/spikes/device-checklist.md` "Mac hands-on rows". New files under `apple/IrisMac` need `make generate`.

- **Mac server binding** (Wave 19 M1, TDD §5): `MacCaptureStack` gives `CaptureStack` the saved connection's `serverKey` (work for another server is held back); `MacCompositionRoot.serverBox` is the `serverKey` of every `HistoryModel` it makes (stale answers dropped), and created memos reach History through `CreatedMemoLog.setServerHandler` + `insert(_:origin:)`.

- **Mac popover** (`docs/design/mockups/mac.html` variant `menu`): `MacMenuPanel` is the quick-access surface, `Theme.Spacing.menuWidth` wide (roles `menu*` in `Spacing.swift` with the CSS source), one page: `MacHomePage` has the title + the Hermes and Transcribe pair (`root.recording.toggle(mode:)`; the Hermes button shows the `.toggleTake` shortcut, the hotkey stays Hermes), the newest 5 memos as `MacMemoRow` (a click opens the main window on that memo, `root.show(id)`; context menu from `MacMemoActions`), the lines Open Iris (⌘O), Settings… (⌘,), Check for Updates… (only when the root has an updater, i.e. not under `-IrisFakeData`) and Quit Iris (⌘Q), and the connection line, which appears only while the link is not connected (`MacConnectionStatus.isShown`: connecting, unreachable, token rejected, not configured; the sidebar footer follows the same rule); with an update waiting, the Check for Updates… line carries "Version x available" in the accent colour; with nothing saved a "Set Up Iris" button opens the onboarding window. The popover's list is always the unfiltered `root.history`.

- **Mac desktop app** (windows, not pages): three scenes declared in `IrisMacApp`, opened by the always-present `MenuBarLabel` when the root's counters change (`windowRequest`, `onboardingRequest`, `settingsRequest`; LSUIElement apps need `NSApp.activate()` first). `MacActivationPolicy` makes the app `.regular` (Dock, ⌘Tab) while a visible titled window that can be main exists and `.accessory` again after the last closes (pure rule `policy(for:)`; popover and recording panel are panels and never count). A Dock click or a Finder/Spotlight launch of the running app reaches `MacAppDelegate.applicationShouldHandleReopen`: `MacActivationPolicy.reopenAction(mainWindowOpen:needsOnboarding:)` always ends on the main window: it opens it, or raises it while `root.isWindowOpen` (a visible Settings, Sparkle or artifact window does not count as the main one), and opens the onboarding instead when nothing is saved; both ask `root.showMainWindow(source: "dock")`, logged as `mac.window` with source `dock`.
  - **Main window "Iris"** (`MacMainWindow`, 1100x720): `NavigationSplitView` sidebar | list | detail. `MacSidebar` (Library: All memos, Favorites, Archive; Threads; under them `MacSidebarFilter`: the kinds of `root.filterKinds` (the window list plus the popover's unfiltered memos) and the iPhone sheet's states Failed and Done as toggles over `windowHistory.filters` through `root.toggleKindFilter` / `toggleStateFilter`, a Clear link while one is on, kept across scope changes by `MacLibraryScope.apply`) selects `root.scope` (`MacLibraryScope`; Favorites shows the number of favorites in the popover's unfiltered list, `n+` when more pages exist than are loaded (`MacFavoritesCount`, no route of its own)), which maps onto `HistoryFilters` (Threads = `setThread(true)`). The window has its own `root.windowHistory` (replaced on a connection change); it takes no stream of its own (the fake client has one consumer): `StreamTappingClient.mirror` hands every event of the popover's single stream to `followWindow`, handled only while the window is open (`windowDidAppear` / `windowDidDisappear`). `MacMemoList` (native `List(selection: $root.selectedMemoID)`, day sections, `.searchable`, Delete key, Space plays the recording; **the macOS `List` clips a row to 24 pt unless both `.environment(\.defaultMinListRowHeight, …)` and the row's `.frame(minHeight: …)` carry `Theme.Spacing.macRowMinHeight`**). `MacMemoDetailPane` lays a memo out as a **chat** when `Memo.isConversation` (IrisCore, the iPhone's rule: every non-deleted Hermes memo, before `act` too; once a model has shown a chat it stays one): the header (headline 18 pt, kind chip, one metadata line), `MacConversationView` (IrisUI's `ConversationTurnList` with `Style.mac`, the iPhone's turn views at `textRole: .footnote`, from `ConversationTimeline.entries(of: thread)` once `GET /v1/threads/:id` has loaded, else `entries(of: memo)` from the memo itself, so the list's copy shows at once and an unreadable thread still shows the memo's turn), and `MacComposerBar` pinned under the scroll view (`safeAreaInset`). Details are the toolbar's info button (`mac.detail.details`, `MacMemoDetailModel.isShowingDetails`): a popover (`MacMemoDetailsPopover`, 320 pt wide, as tall as its content up to 520) with IrisUI's `MemoDetailsContent` (the iPhone sheet's view: steps with Retry, copy rows, "Hermes used", ids) set to `.detailsDensity = .desktop`: the Mac type scale (`macFont`) and tighter insets, where the phone's roles read oversized, per answer: Previous/Next step through the thread's memos, the open memo uses the pane's model, every other one a model of its own (`MacCompositionRoot.detailsModel(for:)`) that loads its steps. A transcribe-mode memo keeps the document layout (`MacMemoSections`: Reply via `MessageContentView(textRole: .footnote)`, Summary, Transcript; Details in the toolbar popover) and has no composer. The pane reloads on the open memo's revision, on every memo of its thread and on stream returns, so a running turn (pending bubble with the dashes) becomes its answer in place; the scroll view opens at the newest turn. Mermaid blocks render as the server PNG (`root.replyImages`, injected as `\.replyImageStore` on `MacMainWindow`); a tap opens `MacDiagramSheet`. A list row of a memo in flight shows a mini spinner in place of its status dot (`MacRowStatusMark`; the dot under Reduce Motion).
  - **Typing** (owner feedback, Issue 131): `MacComposerBar` (growing field 1 to 8 lines; Return sends, Shift-Return a new line, Command-Return always; a Send button, a menu "Send to Hermes" / "Transcribe only" on a new memo; counter past 80 % of the 20 000 limit; `ComposerModel.failure` as a red line; the "Queued" note for 4 s; a microphone on the New memo page starts a Hermes take) over the iPhone's `ComposerModel`. `MacCompositionRoot.composer(for: threadId)` is one model per conversation (nil = the New memo page, `MacNewMemoPage`, shown when `selectedMemoID` is nil), cleared on a connection change; `sendTyped(_:mode:)` clears the text on `.sent` / `.queued`, keeps it on a refusal; a new memo selects the created memo, a reply stays in its conversation (`MacMemoDetailModel.didSend`). Typed memos go through `root.textOutbox` (production: the capture stack's `OutboxService`; `-IrisFakeData`: a fake-pipeline outbox on the fake API, `-IrisFakeStepMs <n>` sets its stage time), and the created log of either feeds the popover's and the window's lists. Entry points: the window toolbar's New memo (⌘N, `root.newMemo()`) and Transcribe (⇧⌘T, `MacTranscribeButton`, `root.toggleTranscribe()`: the popover's transcribe-only take with the recording panel, Stop while any take runs) and the popover's "New memo…" line. Toolbar (`MacDetailToolbar`, one row of grey icons, no overflow menu): the speaker (`mac.detail.play-reply`: a single icon with no chevron segment; idle it opens a menu with `variant=summary` and `variant=full`, `MacSpeakerEntries`, while a reply reads it is a Stop button; `MacAudioPlayer`, a bare `AVPlayer` over `MediaDownloader`, no `AVAudioSession`, keeps one clip per memo and form; the menu has no primary action because the gesture that opens a menu behind a hidden indicator is not verified on a device), copy (`mac.detail.copy`: a plain button that copies at once when one thing can be copied, the transcript of a transcript memo; a menu only when transcript and reply both exist, `MacMemoDetailModel.copyTargets`), retry, the user's own recording as a direct `waveform` button (`mac.detail.play-recording`, a stop glyph while it plays; a waveform, not a speaker, so it is not mistaken for the reply), details, favorite, archive, delete (undo toast via `macToast`). Every control sets `macToolbarInk()` (the system label color): the window's `.tint` is the accent and would colour a Menu, so the toolbar reads grey and only a state shows (`star.fill`, the stop glyphs). The Transcript section of the document layout has a small Copy at its label (`mac.detail.transcript.copy`, the whole text of every part), and a Transcribe row in the window list and in the popover shows a Copy button while the pointer is over it (`MacRowCopyButton`: the whole transcript of a continued one too, read through `MacCompositionRoot.wholeTranscript(of:)`; `Memo.macRowCopyText` gates it; the row's context menu has Copy transcript too), with the same "Copied" confirmation. Every toolbar control and context-menu entry takes its `.help` from `MacMemoControl` (one table, tested over `allCases`): a new control needs a case. `root.selectedMemoID` / `show(_:)` is the one selection, cleared on a connection change.
  - **Conversation, keyboard first** (Issue 883): the popover's `MacQuickAsk` line (`root.quickAskComposer`, its own draft) takes the keyboard each time the popover becomes key; Return sends a Hermes memo and `root.quickAnswer` (a `MacMemoDetailModel` of the new memo, fed by `history.liveEvents()`) shows the question and the streaming answer under the line, with Open in window (`openQuickAnswerInWindow`, selects the memo) and Done; the window's selection is not touched. `MacMemoDetailModel` folds `memo.delta` / `memo.activity` into `LiveTurns` exactly as the iPhone's `ThreadModel` (working list, then a `.streaming` turn with the id `<memo>.reply`; `seedLive` takes `partialReply` as the base; the pane feeds it from `windowHistory.liveEvents()`). `MacPromptField` is the one field of both surfaces: Return sends, Shift-Return inserts at the caret (`PromptCaret`, over `TextField(selection:)`), Escape leaves it in the composer bar; Command-L focuses the bar, a conversation opens with it focused, Command-N stays New memo. The bar's microphone is in threads too: `root.talk(in:)` → `RecordingPanelModel.toggle(mode:threadID:)` → `TakeEngine.start(mode:threadID:)` (a `TakeRequest` with `threadID`, not hold-to-talk). The global key continues `root.frontConversationThreadID` (the open memo's Hermes session while `isMainWindowFront`, set from `controlActiveState`), else starts a new memo. The main window opens at a launch by the user: `installLaunchDetection` reads the open-application event (`MacLaunchOrigin`: the `lgit` property marks a login item; **not device-verified** for `SMAppService.mainApp`), `launchDidFinish` sets `launchWindowPending` from `MacLaunchOrigin.opensMainWindow(needsOnboarding:)` (true for a launch by the user, false for a login launch or while the onboarding opens instead), and the menu-bar label takes it once. Snapshots `menu-ask` (a question sent from the popover, taken when the stream shows) and `window-streaming` (emitted events on the running sample memo).
  - **Settings scene** (⌘,, `MacSettingsView`): tabs Connection (URL, token, Test connection, Save, status), Recording (`KeyboardShortcuts.Recorder`), General (launch at login via `SMAppService.mainApp`, the version and build from the bundle (`AppVersion`), and with an updater the update state (`UpdateStateRow`: Not checked yet, Up to date, or Version x available with Install…), Check for Updates…, Quit). No microphone or spoken-reply setting on the Mac. `root.settingsTab` selects the tab (the snapshot run).
  - **Basalt shell** (Issue 1695): the window's chrome and every pane take surface, ink, separators, selection and accent from `Theme` tokens, as the conversation does. Sidebar `Surface.panel`, list and detail `Surface.background`, Settings forms `Surface.background` with their grouped sections on `Surface.panel`, the recording panel `Surface.elevated`; row text `Ink.primary` / `Ink.muted`, separators `Surface.hairline`; the window's `.tint` is `Accent.fill`, so the native selection and focus rings wear the accent (the toolbar controls opt out, see Toolbar), and the title bar and toolbar strip take `Surface.background` (`.toolbarBackground(_:for: .windowToolbar)` on the window), so the strip reads as one surface with the panes; the native look of the strip's buttons stays. The helpers are in `MacShellStyle.swift` (`macShellList`, `macRowInk`, `macSettingsPane`, `MacShellDivider`). A row's explicit ink flips to `Accent.onFill` while the row is the emphasized selection (`backgroundProminence`). No `.secondary`, no `Color(nsColor:)` and no `Material` is left in `apple/IrisMac`, except what the platform does better than a repaint and stays native on purpose: the sidebar's translucency is gone, but the list selection and arrow keys, the focus ring, the toolbar's buttons and the window controls, the Settings tab strip and the buttons, toggles and fields inside the forms (the system's controls), `NSColor.systemRed` of the recording menu-bar icon (`IrisMacApp`), and, in the DEBUG-only snapshot run, `.regularMaterial` behind the speaker menu's entries (it pictures the system's menu).
  - **Onboarding** (`MacOnboardingView`, 480x420): opens at launch when `root.needsOnboarding` (production, nothing saved) and from the popover's connect prompt; Continue is enabled once Test connection passed, saves, closes the window and opens the main window.
  - **Type and spacing:** the desktop uses `macFont(.caption|.body|.lead|.title)` (11 / 13 / 15 / 18 pt, `Theme.MacTextRole`), not the iPhone's basalt `themeFont` roles; spacing roles are `mac*` / `window*` in `Spacing.swift`. Window events are `mac.window` (`MacEvents.window`: window name, action, source; no memo).
  - `-IrisMacSnapshot <dir>` (fake composition) writes `menu` (also `-dark`), `menu-ask`, `window-all` (also `-dark`), `window-shell` (also `-dark`: sidebar, list and conversation side by side in a window of ours, because the main window's own picture is blank on a host with no display), `speaker-menu`, `window-thread`, `window-chat-mermaid`, `window-running`, `window-streaming`, `window-thread-failed`, `window-transcript`, `window-filtered`, `window-toolbar-transcribe`, `window-toolbar-stop` and `sidebar-filtered` (each also `-dark`), `window-filter-active`, `window-new`, `window-composer`, `window-sent`, `window-answered`, `settings-connection` (also `-dark`), `settings-recording`, `settings-general`, `onboarding`, `recording`, `recording-longmic`, `recording-refused`, `window-toolbar-detail-conversation` and `window-toolbar-detail-transcript` (each also `-dark`: the real toolbar's controls in a strip of ours on the window tint), `window-transcript-pane` (also `-dark`: the Transcript section with its Copy), `window-details-transcript` (also `-dark`), `artifact-island`, `artifact-island-dark`, `artifact-cards`, `artifact-cards-dark`, `artifact-viewer`, `artifact-viewer-dark`; run it with `-AppleLanguages "(en)"` or `"(de)"` (window titles are localized; `make proof-apple` runs both, English into `mac/`, German into `mac-de/`). Windows with chrome are captured through `CGWindowListCreateImage` looked up with `dlsym` (the SDK marks it unavailable; it answers for the app's own windows without a Screen Recording grant); `cacheDisplay` leaves the sidebar, materials and toolbar blank.

- **Mac outbox panel** (Wave 19 M1, TDD §5): a strip under the panel header while the queue holds something (`MacOutboxStrip` / `MacOutboxModel` over `OutboxService`, the iPhone's
  `QueuedItemSource`: a count, a stalled item's reason, Retry now / Discard; `-IrisMacStalled` seeds it on fakes; put it after `-IrisMacSnapshot <dir>`: a launch flag between `-IrisMacPanelWindow` and `-IrisMacSnapshot` stops the panel window from being created).

- **Mac telemetry** (Wave 19 M1, TDD §5): the Mac writes the same device records as the iPhone with `service.name=iris-macos` (`MacTelemetry` builds the `DeviceLog`; `DeviceLog`,
  `DeviceLogCaptureEvents` and `ObservedSegmentUploader` are compiled in): add an event as `MacEvents` / `DeviceLog.event`, never a bare `Logger` call, and never a transcript, reply, park
  reason, banner text, token, URL or device id in one. Mac-only names: `mac.panel`, `mac.window`, `mac.hotkey`, `audio.input_switch`, `audio.input_recovery`, `notify.mac`, `outbox.user_action`, `app.lifecycle`.

- **Mac notifications** (`MemoNotifier`, TDD §5) announce a **transition** into finished (`notified`) or failed (the title is the memo's kind), from the open event stream
  (`memo.updated` / `memo.done` states) and from the catch-up after each `ready`: an unfiltered fetch of the newest 50 memos (the first of a connection is the silent
  baseline; later ones announce memos that reached a kind meanwhile, at most 5, newest first). A state that is not a kind clears the record, so a retried memo announces
  again; the memo is fetched fresh before it posts. Banners never carry the transcript, reply or park reason. A connection switch withdraws the old server's banners
  (and one posted during the switch); **known limit:** the Mac notifier announces from its open event stream only, so a memo that finished while the app was not running is not announced (APNs alerts reach the devices that registered a token, not this notifier).

## Updates (Sparkle)

- `SparkleUpdateEngine` hands Sparkle a delegate (`UpdateRelay`) and reports what a check found as `UpdateStatus` (`unknown`, `upToDate`, `available(version, build)`): `updater(_:didFindValidUpdate:)` (it also fires for an update Sparkle resumes after a relaunch) and `updaterDidNotFindUpdate(_:error:)`. `Updater.status` is observable; the main window's toolbar (`UpdateBadge`) and the popover's update line show a mark only while `available`, Settings > General always shows the state. Install… calls `checkForUpdates()`, which makes Sparkle show its own window with the update it found. The snapshot run scripts the engine (`ScriptedUpdateEngine`): `settings-general`, `settings-general-update`, `window-update`.
- **Why two updates came one after the other (0.3.0 build 811, then 0.3.1 build 816):** the appcast holds only the newest build (`scripts/mac-release.sh` generates it from one archive), so the second offer did not come from the feed. Sparkle keeps an update it already downloaded and staged and, on the next launch or scheduled check, resumes it (`SPUUpdater resumeUpdate:` / `resumeInstallingUpdate`) without reading the appcast again: so build 811, downloaded and staged before 816 was published, was offered and installed first, and the check after the relaunch found 816 (read from Sparkle 2.10.1's source; the owner's machine was not inspected). The resume path skips `updater(_:shouldProceedWithUpdate:updateCheck:error:)` too, so no delegate callback or setting can cure it short of discarding the staged download; the cost is one extra update after a release that follows another within hours. Not changed.
