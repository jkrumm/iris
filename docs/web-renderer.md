# Web renderer (web/)

Contract between the page and the host, the CSP, the build rules and the library measurements. Rules to follow when changing `web/`: `web/AGENTS.md`. Research and host contract: `docs/research/2026-11-webview-island.md`; artifact kinds: TDD "Reply artifacts".

One static page (Vite 8, React 19, strict TypeScript, bun) that the iOS/Mac WebView island loads from the app bundle; research and host contract: `docs/research/2026-11-webview-island.md`, artifact kinds: TDD "Reply artifacts".
The host calls `window.iris.render({artifact, theme})` once after load and again on change (`src/render.tsx`).

- **Payload** (`src/payload.ts`, hand-written guard `parsePayload`): `artifact` is `{kind: "show", spec}` (a `iris-show` spec as JSON) or `{kind: "doc", format: "markdown" | "html", title?, content}`; `theme` is `{scheme: "light" | "dark", vars?}`. The host sets the `--iris-*` variables on `<html>` at document start (`ArtifactTheme.swift`), the page styles itself with `var(--iris-*)` only (fallbacks are the light values), no `prefers-color-scheme`. `vars` is applied to `<html>` when present (harness and tests only); `scheme` sets `color-scheme` and `data-scheme`, and a chart is rebuilt so it re-reads the token colors. A bad payload or an invalid spec renders one notice (`src/messages.ts`), never throws, never shows spec content (an error boundary covers the renderers).

- **Show specs** (`src/show/`): table, chart (bar, line, area, pie), stat, list, callout. `src/spec.ts` validates against `contracts/schema/artifacts.show-spec.json` (the file the server exports) with `@cfworker/json-schema` (no eval) plus the zod refinements JSON Schema cannot express (row length = columns, series length = x, a pie has one series). The island has no inner scroll: tables wrap (`table-layout: auto`, `overflow-wrap`), nothing is `overflow: auto`.

- **Markdown docs** (`src/doc/Markdown.tsx`): react-markdown, remark-gfm, remark-math, rehype-katex, rehype-highlight (14 registered languages: js, ts, json, bash, python, swift, sql, yaml, diff, css, xml, markdown, go, rust; token colors from the `--iris-*` tokens in `styles.css`). No `rehype-raw`: raw HTML never passes through. Links are plain `<a href>` (the host intercepts activations); only `data:image/` images render, any other image renders its alt text. KaTeX fonts: woff2 only, flat `KaTeX_*.woff2`.

- **HTML docs** (`src/doc/HtmlDoc.tsx`): `<iframe sandbox="" srcdoc scrolling="no">`, no `allow-same-origin`, no script. The parent cannot read the frame's height, so the frame is a fixed `HTML_DOC_HEIGHT` (480 px): a taller document is cut off (the island has no inner scroll), a shorter one leaves blank space. **CSP finding (open host question):** a `srcdoc` frame inherits the embedding page's CSP, and the host serves the page with `ArtifactSchemeHandler.bundledPolicy` (`style-src iris-artifact:`, no `'unsafe-inline'`), so the document's inline `<style>` and `style=""` are blocked ("Refused to apply inline style", asserted by `tests/csp.spec.ts` in Chromium under the same policy with `'self'` for the scheme) and the document renders unstyled; a base style prepended to the srcdoc cannot work either (also inline). The frame's own canvas is white (`color-scheme: light`) so unstyled black text stays readable in dark mode. The fix is on the host, and the host does it (Issue 728): an HTML document is served through its own `.html` entry (`documentPolicy`: inline styles, no script) and never reaches this page, so this path is unused by the apps. WebKit was not tested here (Chromium only): whether `frame-src`/`default-src 'none'` blocks a `srcdoc` frame in WebKit is unverified.

- **Height and bridge:** the host's injected script (isolated world) runs the ResizeObserver and posts `height` / `ready`. **The page carries no bridge code** (the handler does not exist in the page world). The page's duty: `html, body {height: auto; overflow: hidden; margin: 0; background: transparent}`, no viewport units, document height = content height. `tests/height.spec.ts` installs a stand-in for the host script.

- **CSP and build rules.** `index.html` carries a meta CSP (`default-src 'none'; script-src 'self' iris-artifact:; style-src 'self' iris-artifact:; img-src 'self' iris-artifact: data:; font-src …; base-uri 'none'; form-action 'none'; frame-src about:`). `'self'` for a custom scheme is matched by WebKit by scheme + host + port, so it covers `iris-artifact://app` and the http test origin; the host header's `iris-artifact:` scheme-source works too (both are listed). No inline `<script>` or `<style>` in the page, no `style="…"` text at runtime (React style objects and Chart.js set styles through CSSOM, which the policy allows), no `eval` / `new Function` (`@cfworker/json-schema` and Chart.js do not need them; the built bundle has neither). The host serves only flat names `[A-Za-z0-9._-]+`: the build is one classic IIFE script at the end of `<body>` (no `type="module"`, no `crossorigin`), stable unhashed names `index.html`, `artifact.js`, `artifact.css`, `KaTeX_*.woff2`, relative URLs, no sourcemaps (`vite.config.ts` plugins `classicScript`, `katexWoff2Only`). Builds are byte-reproducible (pinned exact dependencies, `bun.lock`, nothing embeds a path or time; the Linux build equals the macOS one).

- **Change it:** edit `web/`, run `make web-build` (builds in a temp dir, deletes every file in `apple/Packages/IrisUI/Sources/IrisUI/Resources/Artifact/` except the spike's `island.{html,css,js}`, copies the build), commit the bundle with the source; `make check-web` fails on drift ("run make web-build") and above the 1.5 MB gzip budget. The dev harness (`bun run dev`, `harness.html`; never in the bundle) renders every contracts fixture plus `web/fixtures/` through the same `window.iris.render`, with a scheme and width toggle; `src/dev/theme.ts` mirrors the host's token values (dev only, a test compares its key set with `ArtifactTheme.swift`). Playwright (`web/tests/`, chromium, 390 px, scale 2) screenshots one fixture per image through `harness.html?fixture=<name>&scheme=<light|dark>`; the server in `tests/server.ts` sends the host's `bundledPolicy` header (`'self'` for the scheme). Baselines are Linux renders in `web/tests/__screenshots__/`: re-record only with `make web-snapshots` (Playwright image tag = the pinned `@playwright/test` version, `PLAYWRIGHT_VERSION` in the Makefile; bump both together).

- **Libraries (measured 2026-11-10, gzip -9 of the built output):** total 563 KB (`artifact.js` 298 KB, `artifact.css` 5 KB, 19 woff2 fonts 260 KB as is). Charts: Chart.js 4 with only the bar, line, pie controllers, their elements, category + linear scale, Filler, Legend, Tooltip registered (canvas, no animation, fixed 220 px). Markdown: react-markdown + the remark/rehype stack above; rehype-highlight imports lowlight's `common` (37 languages) as its default, which kept all of them in the bundle: `vite.config.ts` aliases `lowlight` to `src/doc/lowlight-lite.ts` (empty `common`), which saves 42 KB gzip (339 KB to 297 KB). Streamdown was rejected on size: `streamdown` 2.7.1 alone bundles to about 300 KB gzip (1.0 MB minified) before math, charts or highlighting, it carries `rehype-raw` (raw HTML) and `rehype-sanitize`, and its code plugin (`@streamdown/code`, shiki 4) bundles to 1.97 MB gzip over 390 chunks (one grammar per language), against 0.30 MB for our whole script.
