# Validate reference

What each target runs and where, the Apple CI jobs, the machine budget and simulator memory. `make help` lists the targets with one line each; this page carries the detail it cannot. Root summary: `AGENTS.md` (Validate).

| Target | Runs | Where |
|-|-|-|
| `make check` | `check-server` (oxlint, `oxfmt --check`, `tsc --noEmit`, `bun test`), `check-contracts`, `check-strings`, `check-web`, `guard`, and `check-apple` wherever `xcodebuild` exists | mini, CI (`check.yml`, no Apple on Linux) |
| `make e2e` | the pipeline against a fake-booted server (needs ffmpeg) | mini, CI after `check` |
| `make check-web` | `web/`: oxlint, `oxfmt --check`, `tsc`, unit tests, `build:check` (committed bundle = fresh build, gzip budget), Playwright e2e (installs Chromium itself; network, CSP, height; screenshots only with `WEB_VISUAL=1`, the Linux default; `WEB_E2E=0` skips the e2e) | mini, CI (`check.yml`: `check` job with `WEB_E2E=0`, job `web` in the Playwright image with `WEB_VISUAL=1`) |
| `make web-build` / `make web-snapshots` / `make web-check-linux` | rebuild and sync the bundle (commit it) / re-record the Linux baselines in the pinned Playwright image / run the e2e with screenshot comparison in that image | mini (docker via Makefile only) |
| `make check-apple` | Theme drift, `check-strings`, `swift format lint --strict`, `swift test` per package (macOS host), `xcodebuild build` of `Iris` + extensions (simulator) and `IrisMac`, then `IrisMacTests` (hosted in the Mac app, `-IrisFakeData`: notifier, composition root, detail model) | mini, CI (`apple.yml`) |
| `make snapshots` | IrisUI snapshot tests on the pinned simulator (`RECORD=1` re-records) | mini, `apple.yml` (job `snapshots`) |
| `make uitest` | XCUITest flows (`-IrisFakeCapture`); `ONLY="<Class>[/<test>] …"` runs those classes or methods (`-only-testing:IrisUITests/…`), `UNIT=1` adds `IrisTests` | full suite: `apple.yml` nightly and dispatch; a push or PR runs a subset; mini: `ONLY=` only |
| `make device` | `device-build` + `device-run`: signed Debug build, install, launch and a phone screenshot on the paired iPhone (see Device) | mini, phone wired |
| `make testflight [UPLOAD=0\|1]` | `scripts/testflight.sh`: archive `Iris` Release, export a signed `.ipa` into `.artifacts/testflight/export` (`UPLOAD=0`, default) or export-and-upload (`UPLOAD=1`, needs the App Store Connect app record); `CFBundleShortVersionString` = `bun scripts/version.ts` (see Versions), `CFBundleVersion` = `<git rev-list --count HEAD>.<UTC epoch hours>` (strictly increasing, so a same-sha weekly rebuild uploads); `DRY_RUN=1` prints version, build and notes and stops | mini, under the Apple lock; the poller's release hook runs it |
| `make check-strings` | the String catalogs: `de` on every key, no stale key, no hard-coded user-facing literal (bun only, runs on Linux CI too) | mini, CI, `check`/`check-apple` |
| `make mac-release IDENTITY=development\|developer-id [PUBLISH=draft\|release]` | sign, zip, appcast and GitHub release of `IrisMac` (see Mac releases; `DRY_RUN=1` prints version, tag and notes only); under the Apple lock | mini |
| `make merge-guard` | run right before merging a PR: the branch contains `origin/master`, master's last `check.yml` run is green, and the **exact head** has a finished green `check.yml` run, plus a green `apple.yml` run when the branch changes a path that workflow is filtered on (the guard reads the `pull_request` `paths` from `apple.yml` itself). `MERGE_GUARD_ARGS=--wait` polls while the head's runs are still going (45 min), `--allow-red` only for the change that fixes a red master (never skips the head's runs), `--no-fetch` skips the fetch | mini, the factory lead |
| `make check-fast` | the lead's tier (`project.yaml` `checks: {fast, full: make check, ci: true}`): `check-server`, `check-contracts`, `check-strings`, `check-web` with `WEB_E2E=0`, `guard`, and where `swift` exists the Apple theme drift + `lint-apple`, plus `test-packages` only when `apple/` differs from `origin/master`. No simulator, no `xcodebuild`. CI runs the full gate on the PR head; a lead relies on it, never runs `check-apple`, `snapshots` or `uitest` locally except to reproduce a CI failure (one targeted run) | mini |
| `make guard` | public-repo scan (IPs, tailnet/real hostnames, token shapes) | mini, CI, lefthook pre-commit |
| `make verify` / `make smoke` | production health / a real recording through production | mini only, after deploy |

**`apple.yml`** runs three jobs that start together on hosted `xcode-27` runners (public repo: parallel costs nothing): `check-apple` (`make check-apple`), `snapshots` (`make snapshots`) and `uitest`. Each restores an `actions/cache` entry of SPM checkouts and DerivedData (`.github/actions/apple`; key = Xcode build + hash of `apple/project.yml` and the package manifests, falling back to the newest entry of the same job; the `Package.resolved` files are untracked) and a push or `workflow_dispatch` or the nightly saves a new one (a PR only reads). `uitest` on a push or PR runs `IrisTests` plus the XCUITest classes whose screens changed: `scripts/uitest-select.ts` diffs against the base and maps the changed files through `scripts/uitest-map.json` (path globs → classes; the smoke class when nothing maps; `ALL` when `project.yml`, a UI-test helper, the sample data (`Sample*.swift`), the Makefile or the workflow changed) and logs the files and the classes it chose (`uitest subset:` lines, also the job summary). New screen or class: add it to the map (`bun test scripts` fails on a class the map does not name, a class that does not exist, or a glob that matches nothing). The full suite runs nightly (02:17 UTC, default branch) and on `workflow_dispatch`. `snapshots` builds in `apple/.dd.noindex`, the app build's derived data, so Textual is compiled once per runner. A new push cancels a PR's stale run, never a master run. Locally run `make snapshots` plus `make uitest ONLY=…` for the screens you touched, on one simulator. Never re-run the full suite locally to bisect: read the CI log and run the failing test alone.

**Machine budget (reset row 7b, mechanical):** locally **at most one targeted Apple run per change; CI proves the rest.** Every heavy target (`check-apple`, `build-apple`, `test-packages`, `snapshots`, `uitest`, `sim`, `run-sim`, `screenshot`, `ui-snapshot`, `proof-apple`, `device`, `device-build`, `device-run`, `testflight`, `mac-release`) runs through `scripts/apple-slot`: on the mini that is `lockf /tmp/iris-apple.lock` (one Apple job at a time; the factory's test slots default to two and are host-wide) around `factory slot run --name iris-apple` (waits on contention, runs anyway only when the factory server is down; no slot or lock within the wait = exit 75); in CI, where there is no `factory`, the bare command. No hand-typed `lockf`; a nested target (`check-apple` calls `test-packages`) runs bare inside its parent's slot (`IRIS_APPLE_SLOT`). Targets that boot a simulator (`check-apple`, `snapshots`, `uitest`, `run-sim`, `screenshot`, `ui-snapshot`) run `xcrun simctl shutdown all` inside the slot when they end, failing runs too; before the job they slim the pinned device (`scripts/sim-slim`, below); `make sim` boots one and leaves it for you, `make sim-down` ends it, and `KEEP_SIM=1` on `run-sim` / `screenshot` / `ui-snapshot` keeps it booted for a hands-on session (shut it down after). Runners are capped (outside CI the Makefile's `XCB` also runs under `nice -n 10` with `IDEBuildOperationMaxNumberOfConcurrentCompileTasks=2`, like `scripts/apple-proof.sh`): `xcodebuild test` with `-parallel-testing-enabled NO -maximum-parallel-testing-workers 1` and one destination, `swift test --jobs $(SWIFT_JOBS)` (2). `make uitest` without `ONLY=` refuses outside CI (`CI` set); only an explicit owner request overrides it: `IRIS_FULL_UITEST=1`.

**Simulator memory (Issue 677):** a stock iOS 27.0 iPhone 17 boots ~200 processes / **~11 GiB RSS** at idle (wallpaper posters ~4 GiB, then News, Spotlight, widgets, Siri/intelligence, Health, Maps, Mail, Photos, Screen Time ...) and peaks at **19.5 GiB** (170 processes) under a `SmokeUITests` run; two of those on the mini drove load 83 and 279 and swap exhaustion. `scripts/sim-slim` (run by `apple-slot --sim` and `make sim`/`run-sim`/`screenshot`/`ui-snapshot`, skipped when `CI` is set) disables ~117 launchd services the tests never touch with `launchctl disable` inside the device (persisted by the device, so a boot never starts them). Measured through the slot, same `SmokeUITests` run, passing: **peak 6.6 to 7.0 GiB** (about 90 processes; the app, the UI-test runner and SpringBoard are ~1.1 GiB of it), a 65% cut. Budget: **the simulator's processes stay under 7.5 GiB RSS** (`ps` sum over `RuntimeRoot` / `CoreSimulator/Devices` commands; `make sim-slim SIM_MEASURE=1` boots cold and prints the idle figure). The 6 GiB target is not reached: what is left is the app under test plus the services XCUITest and install need. It runs once per device and host boot (marker in the device's data dir; `simctl erase` re-arms it), `make sim-slim` forces it. Kept on purpose: Accessibility, notifications, Live Activities, location, pasteboard, LaunchServices, the app-extension stack, `nanoregistryd` and the store stack (`itunesstored`, `appstored`, `itunescloudd`, `ams*`): disabling any of those makes the boot or the app install hang (bisected). Never run parallel simulator clones (`XCB_TEST` already pins one worker). A service the tests start needing: remove its label from the list in `scripts/sim-slim` and `make sim-slim`.
