# APNs and Live Activity pushes from Bun

Research-gateway job `9c33fa0c-8cae-4db1-b061-6b2c7ae39d7d`, 2026-10-27, status `ok`. Raw report, not edited; decisions taken from it live in `docs/TDD.md`.

## Bottom line

- **Bun 1.3/1.4 `node:http2` can carry APNs traffic, but not untuned:** it is marked green in Bun's compat matrix, yet Bun's client fires every request before the server's SETTINGS frame arrives and ignores `peerMaxConcurrentStreams`, so cap in-flight streams yourself (~8–20) per session — or use the experimental HTTP/2 `fetch()` client shipped in Bun 1.3.14, which multiplexes to `MAX_CONCURRENT_STREAMS`, queues overflow and retries on REFUSED_STREAM/GOAWAY.
- **Sign the ES256 provider JWT with `jose` 6.2.13** (zero deps, lists Bun as a supported runtime); it signs via WebCrypto, dodging the DER-vs-IEEE-P1363 question that Bun's `node:crypto` leaves undocumented. Refresh on a ~50-minute cadence: Apple's rule is "no more than once every 20 minutes and no less than once every 60 minutes".
- **`@parse/node-apn` 8.1.0 is the pick** — actively maintained (published 2026-04-12, repo pushed 2026-10-26, ≈287,792 weekly downloads), pure-JS, speaks `node:http2` directly, exposes the full APNs header set and Live Activity fields. **`apns2` 12.x is broken on Bun** (issue #96, undici-based, no fix recorded), and **`apn` 2.2.0 is abandoned** (last publish 2022-06-13).
- **Live Activity pushes require** `apns-push-type: liveactivity`, `apns-topic: <bundleID>.push-type.liveactivity`, and an `aps` dict with `timestamp`, `event` (`start`/`update`/`end`), `content-state` — plus `attributes-type` + `attributes` and a mandatory `alert` for `start`. **`apns-priority: 5` does not count toward the hourly budget; `10` (also the default when unspecified) does**, and Apple publishes no numeric budget figure.
- **Registration:** call `registerForRemoteNotifications()` on every launch and hex-encode the token into `/3/device/<hex>`; Live Activity activity tokens and push-to-start tokens come from ActivityKit's `pushTokenUpdates` / `pushToStartTokenUpdates`, never from UserNotifications. Sandbox vs production follows the app's `aps-environment` entitlement; that TestFlight builds are always production is implied by Apple's wording but was **not** stated verbatim on any page retrieved in this run.

## 1. Transport: `node:http2`, and its real limits

Bun's compatibility page lists `node:http2` as 🟢: "Client & server are implemented. 94% of Node.js's test suite passes. The maxDeflateDynamicTableSize, peerMaxConcurrentStreams and streamResetBurst/streamResetRate options are accepted but ignored." ([bun.com/docs/runtime/nodejs-compat](https://bun.com/docs/runtime/nodejs-compat)). Everything APNs needs is present on the session object: `http2.connect(authority, options, listener)` returns a `ClientHttp2Session` with `alpnProtocol`, `remoteSettings`/`localSettings`, `request()`, `ping(payload, callback)`, `goaway(code, lastStreamID, opaqueData)` and `destroy(code)`, and `SecureClientSessionOptions` accepts `ALPNProtocols`, `settings` and `peerMaxConcurrentStreams` ([bun.com/reference/node/http2/connect](https://bun.com/reference/node/http2/connect)).

Three cautions that matter in production:

- **Over-eager request dispatch.** In Bun 1.4.3 an unmodified Bun client emitted 150/150 HEADERS before the peer's SETTINGS arrived, where node v26.3.0 emitted 100; requests above the server's limit get `RST_STREAM(REFUSED_STREAM)`, and more than ~1001 refused streams loses the session. The client reads `#remoteSettings?.maxConcurrentStreams` in `src/js/node/http2.ts` and never reads the `peerMaxConcurrentStreams` option ([oven-sh/bun#44536](https://github.com/oven-sh/bun/issues/44536)). Mitigation is yours to implement: throttle in-flight streams.
- **No cross-process TLS session resumption.** `node:tls` is 🟡 — `pskCallback`, OCSP stapling, the server `newSession`/`resumeSession` events and session ticket keys are missing, so "session resumption does not work across processes" ([compat page](https://bun.com/docs/runtime/nodejs-compat)). Apple asks for an uncached DNS query per new connection anyway ([sending-notification-requests-to-apns](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.md)).
- **Recent fix history.** Bun 1.3.14 fixed use-after-free crashes in `node:http2` when re-entrant JS callbacks invalidated internal stream pointers ([bun.sh/blog/bun-v1.3.14](https://bun.sh/blog/bun-v1.3.14)).

Apple's connection contract: HTTP/2 over TLS 1.2 or later to `api.sandbox.push.apple.com:443` (development) or `api.push.apple.com:443` (production), or on port 2197; required `:method POST`, `:path /3/device/<device_token>`, `authorization: bearer <provider_token>` and `apns-topic`; APNs ignores HTTP/2 PRIORITY frames ([sending-notification-requests-to-apns](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.md)). Critically: "when using an authentication token, APNs allows only one stream until you post a request with a valid authentication token", and APNs may send a GOAWAY whose payload is JSON with a `reason` key ([same page](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.md)) — so a cold session must send its first request before opening other streams, and your client must parse GOAWAY instead of treating it as a generic close. Reuse connections for hours-to-days, send an HTTP/2 PING after an hour of idleness ([same page](https://developer.apple.com/tutorials/data/documentation/usernotifications/sending-notification-requests-to-apns.md)).

**Better Bun-native option:** Bun v1.3.14 added an experimental HTTP/2 client for `fetch()` — ALPN h2 negotiation, one TCP+TLS connection per origin with multiplexing up to the server's `MAX_CONCURRENT_STREAMS` and overflow queued, `RequestInit.protocol` accepting `"http2"`/`"h2"`/`"http1.1"`/`"h1"`, HPACK-preserving keep-alive pooling, and transparent retry of REFUSED_STREAM and graceful GOAWAY up to 5 attempts ([bun.sh/blog/bun-v1.3.14](https://bun.sh/blog/bun-v1.3.14)). It does not support HTTP proxies/CONNECT, Unix sockets, server push or h2c ([same](https://bun.sh/blog/bun-v1.3.14)) — none of which APNs needs. The exact env var/flag that enables it globally is **not** in this report (see unverified). Fallbacks: an `undici` shim (unlikely to help — see apns2 below) or a Go/Rust sidecar with a plain `http2.Transport`.

## 2. The ES256 provider JWT

Header carries `alg` (APNs supports only ES256) and `kid` (10-character Key ID); claims carry `iss` (10-character Team ID) and `iat` in seconds since epoch, no more than one hour from the current time — an older `iat` yields `ExpiredProviderToken` (403) ([establishing-a-token-based-connection-to-apns](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns)). Refresh rule verbatim: "Refresh your token no more than once every 20 minutes and no less than once every 60 minutes… Similarly, APNs report an error if you use a new token more than once every 20 minutes on the same connection" ([same](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns)). Practically: cache one token, rotate around 50 minutes, reuse across reconnects.

Use `jose` — current version **6.2.13**, MIT, zero dependencies, explicitly covering Bun ([npmjs.com/package/jose](https://www.npmjs.com/package/jose)). It exposes PKCS8 key import via `importPKCS8` and JWT signing via `SignJWT` ([jose importPKCS8 docs](https://github.com/panva/jose/blob/main/docs/key/import/functions/importPKCS8.md), [SignJWT docs](https://github.com/panva/jose/blob/main/docs/jwt/sign/classes/SignJWT.md)), and signs through Bun's fully-implemented WebCrypto instead of `node:crypto`. If you sign manually instead: Bun's `node:crypto` is 🟡 on BoringSSL and supports P-256, but whether `crypto.sign(..., { dsaEncoding: 'ieee-p1363' })` is honoured is not documented on that page ([compat](https://bun.com/docs/runtime/nodejs-compat)) — ES256 requires raw `r||s`, not DER, so verify the output bytes before shipping.

It uses `node:http2` directly (`http2.connect`, `session.ping`, `response`/`frameError`/`goaway` events, `tls.connect` with `ALPNProtocols: ['h2']` for the proxy path) against `/3/device/<token>`, `/1/apps/<bundleId>/channels` and `/4/broadcasts/apps/<bundleId>` ([lib/client.js](https://github.com/parse-community/node-apn/blob/HEAD/lib/client.js)). `.p8` auth is `{ token: { key, keyId, teamId } }`. Headers emitted in `Notification.prototype.headers()`: `apns-priority`, `apns-id`, `apns-collapse-id`, `apns-request-id`, `apns-channel-id`, `apns-expiration`, `apns-topic`, `apns-push-type` — the full set the query asks about ([lib/notification/index.js](https://github.com/parse-community/node-apn/blob/HEAD/lib/notification/index.js)), and it exposes Live Activity fields (`pushType: "liveactivity"`, `relevanceScore`, `timestamp`, `staleDate`, `event`, `contentState`, `dismissalDate`) plus iOS 18 broadcast channels. ≈287,792 weekly downloads for 2026-06-25→2026-07-01 ([npm downloads API](https://api.npmjs.org/downloads/point/last-week/@parse/node-apn)). Searching its tracker for "bun" returns zero issues ([issues search](https://github.com/parse-community/node-apn/issues?q=is%3Aissue+bun)) — absence of bug reports, not proof of runtime health, so smoke-test it.

**`apns2` 12.2.0** requires Node ≥20 and depends on `undici ^7.9.0` + `fast-jwt ^6.0.1` ([npm](https://www.npmjs.com/package/apns2)), ships dual CJS/ESM with types ([package.json](https://github.com/AndrewBarba/apns2/blob/HEAD/package.json)) after 12.0.0 went ESM-only and 12.1.0 restored CJS ([CHANGELOG](https://github.com/AndrewBarba/apns2/blob/HEAD/CHANGELOG.md)). v12 replaced `node:http2` with an undici `Pool({ allowH2: true })` and reaches into undici's private symbols `"clients"` and `"http2Session"` ([src/apns.ts](https://github.com/AndrewBarba/apns2/blob/HEAD/src/apns.ts), [src/internals.ts](https://github.com/AndrewBarba/apns2/blob/HEAD/src/internals.ts)). Its `PushType` includes `liveactivity`, but it only builds the `aps` dictionary — no ActivityKit content-state helpers ([push-type.ts](https://github.com/AndrewBarba/apns2/blob/HEAD/src/notifications/constants/push-type.ts)). On Bun it fails: issue #96 ("v12.1 is broken") shows `TypeError: undefined is not an object (evaluating 'res.statusCode')`; the maintainer replied "Okay so I guess undici doesn't work on bun", and a second reporter on 2025-06-11 said they reverted to 11.8 — which the first reporter said had sent ~35k notifications on Bun ([apns2#96](https://github.com/AndrewBarba/apns2/issues/96)). It is the only "bun" issue in the tracker ([search](https://github.com/AndrewBarba/apns2/issues?q=is%3Aissue+bun)); 47,861 weekly downloads ([downloads API](https://api.npmjs.org/downloads/point/last-week/apns2)). Note the npm README still says "requires Node.js v16 or later", contradicting the repo's `engines: ">=20"` — the repo file wins ([npm](https://www.npmjs.com/package/apns2)).

**`apn` 2.2.0** last published 2022-06-13, `engines` ">= 4.6.0", depending on a GitHub tarball `http2` build and `node-forge ^0.7.1` — treat as abandoned and pre-ActivityKit ([npm](https://www.npmjs.com/package/apn)). Other names seen on npm but not vetted: `@fivesheepco/cloudflare-apns2` 13.0.0 (2025-01-04), `@absolutejs/dispatch-apns` 0.2.1 (2026-10-08), `node-pushnotifications` 6.0.0 (2026-05-05).

**Bottom line for Bun:** the dependency surface of `@parse/node-apn` (`node:http2` 🟢, `node:net` 🟢, `node:tls` 🟡) is nominally covered ([compat](https://bun.com/docs/runtime/nodejs-compat)); apns2's undici path is the wildcard that has already failed.

## 4. Live Activity push payload, headers and budget

Apple's article is now titled **"Starting and updating Live Activities with ActivityKit push notifications"**; there is no longer a page titled "Updating Live Activities with ActivityKit push notifications" (that is the WWDC23 session title) — a naming drift worth knowing when you cite it.

**Headers (device pushes).** `apns-push-type: liveactivity`; `apns-topic: <your bundleID>.push-type.liveactivity`; `apns-priority: 5` or `10`. For channel/broadcast pushes `apns-channel-id` replaces `apns-topic` ([ActivityKit push article](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). Apple's curl example posts to `https://api.sandbox.push.apple.com/3/device/$ACTIVITY_PUSH_TOKEN` with `apns-topic: com.example.apple-samplecode.Emoji-Rangers.push-type.liveactivity`, `apns-push-type: liveactivity`, `apns-priority: 10` ([same](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). The `liveactivity` push type "is only available to servers with token-based connection to APNs" ([WWDC23 10185](https://developer.apple.com/videos/play/wwdc2023/10185/)) — certificate auth will not work.

**`aps` keys Apple names:** `timestamp` (current time in seconds since 1970, so the system always shows the most recent update), `event` (`update` to update, `end` to end, `start`), `content-state`, `stale-date`, `dismissal-date`, `relevance-score`, `alert`, and for starting `attributes-type` + `attributes`, plus `input-push-channel` / `input-push-token: 1` on iOS/iPadOS 18+ ([article](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)).

**`content-state` must mirror your Codable type** exactly: "Set the fields for the `content-state` key to match your custom `Activity.ContentState` type… don't use any custom JSON encoding strategies. Custom encoding strategies will result in update failures" ([same](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)).

**`start`:** must set `event: start`, **must include an `alert`**, and must include `attributes-type` and `attributes` (Apple's documented example: `{"aps":{"timestamp":1234,"event":"start","content-state":{"currentHealthLevel":100,"eventDescription":"Adventure has begun!"},"attributes-type":"AdventureAttributes","attributes":{…},"alert":{"title":{"loc-key":"%@ is on an adventure!","loc-args":["Power Panda"]},"body":{…},"sound":"chime.aiff"}}}`) ([same](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). Push-to-start tokens come from `pushToStartTokenUpdates`; devices on iOS/iPadOS 17.1 and earlier cannot start a Live Activity from a push at all, and broadcast pushes cannot start one ([same](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)).

**Alerts on updates:** allowed — an update may optionally carry an `alert` "to alert a person about a critical Live Activity update… to light up their device and display the expanded presentation" on Dynamic Island devices, or a banner elsewhere; Apple's update example includes `title` (`loc-key`/`loc-args`), `body` and `sound: "HeroDown.mp4"` ([same](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). On iPhone/iPad the system shows no regular alert (it shows the expanded Live Activity); on Apple Watch it uses the alert's `title`/`body` ([displaying-live-data](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)).

**Priority and the budget:** "The system allows for a certain budget of ActivityKit push notifications per hour." If `apns-priority` is unspecified, APNs delivers immediately at default priority **10** and counts it toward the budget; exceeding the budget means the system may throttle. `apns-priority: 5` sends a low-priority push "that doesn't count toward the budget", and Apple recommends "a mix of priority 5 and 10" — 5 for minor changes, 10 for changes needing immediate attention ([article](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). **No numeric pushes-per-hour figure is published.** `NSSupportsLiveActivitiesFrequentUpdates = YES` lifts the budget, and users can disable frequent pushes (`frequentPushesEnabled`, observable via `frequentPushEnablementUpdates`) ([same](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)).

**Ending, staleness, ordering, sizes:** an `end` push should carry the final content state; by default an ended activity stays on the Lock Screen up to four hours, and `dismissal-date` overrides that — a past date (e.g. 1663177260) dismisses immediately, otherwise supply "a date within a four-hour window". `stale-date` flips `activityState` to `.stale`. `relevance-score` is relative (Apple's example: 100 important vs 50 less important) and drives Lock Screen order and which activity takes the Dynamic Island; without a score the first-started activity wins. The system ignores an ActivityKit push that arrives after the activity has ended ([article](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). Static plus dynamic Live Activity data, including push payloads, "can't exceed a combined size of 4 KB"; an activity may run eight hours and sit on the Lock Screen up to 12 ([displaying-live-data](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)).

**`apns-expiration` / `apns-collapse-id` for Live Activity pushes** are not mentioned anywhere in the ActivityKit article; their general semantics were not verified here (see unverified).

## 5. Registration, tokens and environments

Enable the Push Notifications capability in Xcode (this adds the APS Environment entitlement) and enable push for the App ID in the developer account ([registering-your-app-with-apns](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns)). Call `registerForRemoteNotifications()`; success lands in `application(_:didRegisterForRemoteNotificationsWithDeviceToken:)`, failure in `application(_:didFailToRegisterForRemoteNotificationsWithError:)` (offline, APNs unreachable, or missing entitlement) ([same](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns)). Register on every launch: "Never cache device tokens in local storage. APNs issues a new token when the user restores a device from a backup, when the user installs your app on a new device, and when the user reinstalls the operating system" ([same](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns)). Tokens are variable length — "Do not hard-code their size" — and the server "must pass this token unmodified back to APNs" ([UIApplicationDelegate](https://developer.apple.com/documentation/uikit/uiapplicationdelegate/application(_:didregisterforremotenotificationswithdevicetoken:))). On the wire the token is the *hexadecimal* form of the `Data` in the path, e.g. `/3/device/00fc13adff785122b4ad28809a3420982341241421348097878e577c991de8f0` ([sending-notification-requests-to-apns](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)).

**ActivityKit is a separate channel.** "You can't use the User Notifications framework to register your Live Activity for push notifications. Instead, you use ActivityKit to obtain a push token" ([article](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). For per-activity updates, call `Activity.request(attributes:content:pushType:)` with `pushType: .token` ([PushType.token](https://developer.apple.com/documentation/activitykit/pushtype/token)); `activity.pushToken` is not populated synchronously, so observe `activity.pushTokenUpdates` — tokens can change mid-activity, the app gets background runtime to report the change, and the server must invalidate the old token ([article](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). Hex-encode it the same way: `pushToken.reduce("") { $0 + String(format: "%02x", $1) }` ([same](https://developer.apple.com/documentation/activitykit/starting-and-updating-live-activities-with-activitykit-push-notifications)). For push-to-start use `Activity<Attributes>.pushToStartTokenUpdates`, listed as iOS/iPadOS 17.2+ ([symbol page](https://developer.apple.com/documentation/activitykit/activity/pushtostarttokenupdates)).

**Environments:** development is `api.sandbox.push.apple.com:443`, production is `api.push.apple.com:443`, port 2197 accepted on either; "Use the production server for your shipping apps and the development server for testing" ([sending-notification-requests-to-apns](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)). Alert notifications use `apns-push-type: alert` with `apns-topic` equal to the bundle ID; Live Activities use `apns-push-type: liveactivity` with `push-type.liveactivity` appended to the bundle ID ([same](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)). The entitlement-driven mapping from build type to environment (development provisioning profile → sandbox; production profile and beta testers → production, hence TestFlight → production) is **not** in this report as a verified claim — see unverified.

## 6. Rich alert notification payload (mutable-content, category, actions)

The `aps` peer-key model — `alert` (`title`/`subtitle`/`body`), `badge`, `sound`, `thread-id` → `threadIdentifier`, `category` matching a registered `UNNotificationCategory` so its actions render as buttons, `mutable-content: 1` routing to a Notification Service Extension, `interruption-level` (`passive`/`active`/`time-sensitive`/`critical`), and custom keys as peers of `aps` (primitive values only, surfaced in `userInfo`) — is standard APNs behaviour, but the specific Apple pages carrying those statements were not successfully retrieved in this run, so **treat this paragraph as unverified** and confirm against Apple's "Generating a remote notification" page before depending on exact values. For sizing: the 4 KB remote-notification limit (5 KB VoIP) is likewise unverified here; the only size figure established in this run is the 4 KB combined Live Activity data limit ([displaying-live-data](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)).

## 7. Recommended shape for the Bun server

One long-lived HTTP/2 connection per environment, provider JWT cached and rotated ~50 min, `@parse/node-apn` 8.1.0 (or a hand-rolled `node:http2` client) with an in-flight-stream cap of ~8–20 and explicit GOAWAY-reason parsing; Live Activity updates at priority 5 by default with priority 10 reserved for state that must land immediately, `timestamp` on every update so stale payloads lose, `stale-date` computed from your own freshness policy, and push-to-start reserved for iOS 17.2+ devices whose `pushToStartTokenUpdates` tokens you have stored.

## What remains unverified

- Whether Bun's `node:http2` handles APNs' GOAWAY JSON `reason` and ALPN h2 negotiation against `api.push.apple.com` end-to-end — test before shipping.
- Whether `crypto.sign(..., { dsaEncoding: 'ieee-p1363' })` is honoured by Bun's `node:crypto`; use a WebCrypto-based signer (`jose`) to avoid the question.
- The exact env var/CLI flag enabling Bun 1.3.14's experimental `fetch()` HTTP/2 client, and its full code sample.
- Current `jsonwebtoken` version and Bun compatibility.
- Whether apns2 issue #96 was fixed in a later undici or Bun release.
- Apple's documented `apns-expiration` and `apns-collapse-id` semantics, and whether they apply to `liveactivity` pushes.
- The `aps-environment` entitlement text and the explicit statement that TestFlight builds are always production.
- Apple's "Generating a remote notification" details for `mutable-content`, `category`, `thread-id`, `interruption-level`, `badge`, `sound`, custom keys and the 4 KB/5 KB limits.
- Bun issue #31499 (`NGHTTP2_FRAME_SIZE_ERROR` with `@cursor/sdk`) — seen only as a search snippet.
- ActivityKit `pushTokenUpdates` availability annotation (the symbol URL guessed did not resolve).
